Self-hosting guide

Shockwave is a plain Python process — no external services required beyond Discord itself. This page covers setup, config, and the handful of gotchas that actually show up in practice.

Before you start

Runtime

Python 3.10+ (tested on 3.12), plus discord.py and numpy.

A bot application

Created in the Discord Developer Portal, with a bot token and two privileged intents enabled.

Setup

01

Create the bot application

In the Developer Portal, create an application, add a Bot user, and copy its token. Under Privileged Gateway Intents, turn on Server Members Intent — Shockwave needs it to see who's in a voice channel.

02

Invite it to your server

Generate an OAuth2 URL with the bot and applications.commands scopes, and grant Move Members, Manage Channels, View Channels, Connect, and Send Messages.

03

Install dependencies

# from the project root
pip install discord.py numpy
04

Add your token

Create a file named token.txt next to bot.py, containing nothing but the bot token on its own line. Keep this file out of version control.

05

Create the data folder

Shockwave stores per-server state in SQLite at data/guildData/serverInfo/main.db. The folder isn't created automatically — make it yourself first:

mkdir -p data/guildData/serverInfo
06

Point commands at your server

Commands currently sync to one hardcoded guild ID. Replace every 526081127643873280 in bot.py with your own server's ID (right-click the server icon → Copy Server ID, with Developer Mode on).

07

Run it

python bot.py

Guild-scoped commands register instantly — slash commands should show up in your server within a few seconds of the bot coming online.

Common issues

"Unknown interaction" error, but the action happened anyway.
Discord requires an initial response within 3 seconds. Commands that move several members at once (/move, /return, /make-teams) can outrun that window on a slow connection or a big roster. This build defers those commands immediately and replies via a followup message once the moves finish — if you're running older code without that fix, that's the mismatch you're seeing.
"no such table: servers" on first run.
This means the database file existed (even empty) before the table-creation check ran. Delete data/guildData/serverInfo/main.db and restart — it'll be recreated correctly.
A command silently does nothing when a required member/role is left blank.
Discord's slash-command UI allows submitting without filling every optional-looking field. Commands that need a specific player (like /choose) check for this and reply with what's missing instead of failing silently.

About this deploy

This documentation site is static and has no build step — Netlify can serve it directly. The bot itself is a long-running Python process, though, so it needs its own always-on host (a small VPS, a Raspberry Pi, Railway, Fly.io, etc.) — Netlify only hosts the docs you're reading right now.
